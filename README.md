## 它是什么

AutoQuill 是运行在你电脑本地的自动化写作工具。它像人一样在浏览器里操作：

1. **选题** —— 自动从知乎创作中心的推荐问题中筛选故事类话题
2. **提取** —— 打开问题页，提取高赞回答全文与互动数据
3. **生成** —— 交给大模型，按你选定的作者文风创作一篇新故事
4. **发布** —— 自动把故事写入知乎草稿，你检查后可手动发布

支持的功能：

| 功能 | 说明 |
|---|---|
| 一键安装 | 安装包安装即用，不需要 Python / 命令行 |
| 独立窗口 | 自带应用窗口（WebView2 内核），不打开浏览器标签页 |
| 首启引导 | 首次打开自动弹出设置向导（Edge → API Key → 知乎登录） |
| 检查更新 | 内置「检查更新」，一键升级（覆盖安装，数据自动保留） |
| 批量生成 | 一次运行多轮，自动选题 → 生成 → 发布草稿 |
| 文风模仿 | 采集某位知乎作者的故事 → 提炼写作风格 → 生成时自动注入 |
| 故事采集 | 自动浏览作者主页，滚动加载并采集全部故事（断点续采） |
| Web 控制台 | 独立窗口内操作（http://127.0.0.1:8787），实时日志、历史故事 |
| 双生成通道 | API 直调（快速稳定）或 免费网页版（浏览器操作） |
| 数据本地化 | 配置、登录态、采集库、成品全部保存在本机 |

## 系统要求

- **Windows 10 / 11**（64 位）
- **Microsoft Edge** 浏览器（系统自带，或从 microsoft.com/edge 安装）
- 一个可用的 LLM API Key（如 DeepSeek，可选——也可以完全使用免费的网页版通道）

> 不需要安装 Python、不需要命令行操作。

## 安装

1. 从发布页下载 `AutoQuill-Setup-4.2.1.exe`
2. 双击运行安装包
   - 若出现 Windows SmartScreen 提示，点「更多信息」→「仍要运行」即可（软件未做代码签名，属正常提示）
3. 选择语言与安装位置（默认装在当前用户目录，无需管理员权限）
4. 安装完成自动启动 AutoQuill（独立窗口，不打开浏览器）

安装位置：`%LOCALAPPDATA%\Programs\AutoQuill\`（可在「开始」菜单或桌面找到快捷方式）。

### 升级

- 控制台右上角点「检查更新」：自动查询最新版本，有新版本会引导你到下载页
- 下载新安装包直接运行即可（覆盖安装），**配置与数据自动保留**，无需重新配置

## 首次使用（三步引导）

首次启动会自动弹出设置向导，按顺序完成：

**① 环境检测 · Edge**
- 已检测到 Microsoft Edge → 自动通过
- 未检测到 → 按提示安装 Edge 后点「重新检测」

**② 配置 API Key**
- 选择服务商（DeepSeek / SiliconFlow-DeepSeek），粘贴你的 API Key
- 点「保存并测试连接」，成功即完成
- 没有 Key？也可以跳过——在控制台「生成通道」切换为 **Web 网页版**（免费）使用

**③ 登录知乎**
- 点击「打开 Edge 登录知乎」，弹出浏览器窗口
- 扫码或短信登录，检测到登录后自动保存并关闭

三项全部完成即进入控制台。之后随时可点右上角「设置」重新打开引导。

## 使用指南

启动 AutoQuill 后自动打开独立应用窗口（内部地址 http://127.0.0.1:8787，也可用浏览器访问）。

### 运行控制（左栏）

| 模式 | 说明 |
|---|---|
| 环节测试 · 选题 | 只自动选题并打开问题页 |
| 环节测试 · 提取 | 选题 + 提取高赞回答（预览提取结果） |
| 环节测试 · 生成 | 提取 + 生成故事并存盘（不发布） |
| 单轮（完整链路） | 选题 → 生成 → 发布草稿 |
| 批量运行 | 多轮生成 + 发布草稿（可设生成/发布数量） |

### 文风提炼

1. 先在「故事采集」输入某位作者的知乎主页 URL（形如 `https://www.zhihu.com/people/xxx/answers`），点「开始采集」
2. 采集完成后，在「文风提炼」选择该作者 →「提炼作者文风」（约 1-3 分钟）
3. 提炼完成自动切换为该文风，之后生成的故事都会模仿它

也可以「提炼通用文风（跨作者）」：用全部采集样本提炼一套通用风格。

### 配置速览（左栏）

- **故事模型**：运行时切换服务商/模型，下次生成立即生效
- **生成通道**：API（付费，快）↔ Web 网页版（免费）
- **浏览器模式**：前台（调试可观察）/ 无头（后台不打扰工作）
- **作者文风**：切换当前注入的文风

### 日志与结果（中右栏）

- 运行日志实时滚动，可关掉「自动滚动」翻阅历史
- 右侧显示提取结果、生成的故事全文、采集结果、历史故事列表

### 停止运行

- 点「停止」按钮中断当前任务（浏览器操作完成后安全退出）
- 直接关闭 AutoQuill 窗口即停止程序（服务随之停止）

## 两种生成通道

| | API 通道 | Web 网页版通道 |
|---|---|---|
| 成本 | 按量付费（API Key） | 免费（使用 DeepSeek 网页版） |
| 速度 | 快 | 较慢 |
| 稳定性 | 高 | 依赖网页变化 |
| 切换方式 | 控制台「生成通道」→ API | 控制台「生成通道」→ Web 网页版 |

> Web 网页版首次使用会打开 DeepSeek 网站，请在浏览器里登录一次你的 DeepSeek 账号。

## 数据与隐私

**你的数据全部保存在本机**，不会上传到任何服务器：

| 数据 | 位置 |
|---|---|
| 程序文件（只读） | `%LOCALAPPDATA%\Programs\AutoQuill\` |
| API Key、模型选择 | `%APPDATA%\AutoQuill\config\` |
| 知乎登录态（Cookie） | `%APPDATA%\AutoQuill\config\browser_state.json` |
| 浏览器配置（独立 Edge 用户目录） | `%APPDATA%\AutoQuill\data\browser_profile\` |
| 采集的故事库 | `%APPDATA%\AutoQuill\data\collected_stories.jsonl` |
| 文风签名 | `%APPDATA%\AutoQuill\data\authors\` |
| 生成的故事 | `%APPDATA%\AutoQuill\output\` |
| 运行日志 | `%APPDATA%\AutoQuill\logs\` |

要点：

- API Key 仅保存在本机配置文件，仅用于直连你选择的模型服务商
- 知乎登录态用于采集与发布，仅在本机浏览器会话中使用
- 程序从不收集或上报任何使用数据
- 安装包内**不含任何密钥**——干净安装时没有任何人的 API Key

## 卸载

- 「设置」→「应用」→ 找到 AutoQuill → 卸载
- 卸载只删除程序文件，**保留** `%APPDATA%\AutoQuill\`（你的配置与数据）
- 想彻底清空数据，卸载后手动删除 `%APPDATA%\AutoQuill\` 目录即可

## 常见问题 FAQ

**Q：安装时 Windows 提示「未知发布者」/ SmartScreen 拦截？**
A：软件未做商业代码签名，属正常提示。点「更多信息」→「仍要运行」。安装后使用不受影响。

**Q：必须配置 API Key 吗？**
A：不是。可以跳过第 2 步，在控制台把「生成通道」切到 Web 网页版（免费）即可。推荐配置 API Key，速度更快更稳定。

**Q：知乎登录一直失败 / 提示登录失效？**
A：点右上角「设置」重新打开引导，重做第 3 步登录。注意登录要在弹出的 Edge 窗口中完成，检测到登录会自动保存。

**Q：采集不到故事？**
A：确认 URL 是作者的「回答列表页」（`zhihu.com/people/xxx/answers` 而非主页）；确认已登录知乎；作者若回答很少或隐私受限可能采集不到。

**Q：生成的故事没发布到知乎？**
A：「单轮 / 批量」才会发布草稿；「环节测试 · 生成」只存盘。草稿可在知乎 App/网页的「草稿箱」找到，确认后手动发布。

**Q：Web 网页版通道需要登录吗？**
A：需要。首次使用时 DeepSeek 网页版会要求登录一次（后续保持登录）。

**Q：能改数据保存位置吗？**
A：支持环境变量 `AQ_DATA_DIR` 指向自定义目录（高级用法）。

**Q：升级安装会丢数据吗？**
A：不会。新版本安装后自动把旧数据迁移到 `%APPDATA%\AutoQuill\`（仅首次，不覆盖已有数据）。

**Q：如何查看运行日志？**
A：控制台日志框实时显示；完整日志在 `%APPDATA%\AutoQuill\logs\`，按日期命名。

| **v4.1.7** | 修复 Web 通道剖析（文风提炼）失败 + 登录态检测提速：DeepSeek 新版 UI 的停止按钮与发送按钮同元素（圆形 primary DIV，无 aria/无 stop 字样），旧 selector 全部失效、完成检测只能靠「文本稳定」兜底——LLM 输出中途停顿 >8s 即误判完成、读回残缺 JSON 解析失败；现按真实浏览器实测 DOM 修复 selector（生成中移除 disabled 类即停止态），稳定判定加 read-back 重读验证（并行调度同步）；剖析失败日志带回复长度+首尾片段（可直接区分「读回残缺」与「LLM 输出无效」）；登录检测：并发轮询加锁去重（不再各自拉起浏览器）+ 切换走 15s 缓存 + 条件 URL 等待（省固定 1.5s 等待） |
