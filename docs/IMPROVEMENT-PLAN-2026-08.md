## 3. 新增（高杠杆能力，按 P0→P2）

### P0-A：反馈闭环接线（core/feedback_loop.py 从桩变实现）
- record_story_published(url, title, meta)：与 topic_ledger.record 合流，落账字段追加 version（core/version.py）、aid、genre、meta.session_id、story_file——以后复盘无需日志反推。
- attach_performance(url, likes, reads, comments, collects)：在 webui/published.py 快照抓取点增量调用，落 data/state/story_performance.jsonl（每条 = aid 的一次观测，天然时间序列）。
- summarize(genre=None)：按题材聚合『日均互动』→ 产出 genre 先验表（冷启动用 08-22 全量快照 + 08-30 快照已有 386 条观测）。

### P0-B：题材反馈加权选题
- 选题打分：topic_score × (1 + w × genre_prior)；权重直接复用 READER_SCORE_*（赞1.0/评3.0/藏2.5，90 天指数衰减——配置已备好）。
- 效果判据：同类题材新文发布后日均赞 ≥ 该题材历史中位数；同质低互动题材占比下降。

### P1：生成-守则对齐 + Web 通道容错
- 守则前置：把 validate_story_format 的扣分点（章节 0 个 -4、引言缺失、量化堆砌、环境空镜）合并为生成 prompt 的『发布前自检五条』。
- Web 容错：deepseek.py 输入框选择器二级回退；连续 2 次失败自动切 API 通道并提示。
- 提取自适应：MIN_ANSWER_LENGTH / MATERIAL_MIN_LIKES 按『本题材历史命中率』微调，消灭 9 次重试轮。

### P2：复盘自动化
- 把本次分析管线（logs → run_events → rows_joined → 报告）收进 tools/version_feedback_report.py（每周一键）；台账带 version 后自动出账。
- 控制台『已发布看板』增加『题材日均互动』列，人工可见反馈梯度。

## 4. 成功度量（一个月后回看）

- 发布率中位数 ≥ 75%（当前三周中位 50%）
- 废稿率 ≤ 10%（当前 8/29 为 17%）且首轮格式通过率 ≥ 90%
- 同题重复 0 次；Web 通道失败周均 ≤ 1 次
- 题材加权上线后：top3 题材日均赞 ≥ 历史中位 1.5 倍
- feedback_loop 三接口全部被调用（不再是死代码），复盘耗时从 1 小时降到 10 分钟

## 5. 明确不做（避免分散）

- 不做『自动直接发布』：人工确认保留（你的选择是最强信号）。
- 不做多平台（小红书/公众号）迁移：先把知乎一个平台的闭环跑通。
- 不复活配方库；不做复杂推荐系统；第一版题材先验就是按类目统计 + 指数衰减。
