## 阅读与记录方法

从用户有权访问的故事页面选取少量、不同类型的作品。先确认阅读权限和实际可读范围，再研究开篇、中段与结尾。目录简介、开篇片段和完整阅读分别记录；页面返回成功、榜单高赞或正文较长，都不能单独证明已经读完。

个人目录和学习台账通过 [本地工具](../tools/story_study.py) 保存。工具只做记录和查询，不访问知乎，不读取登录态，不调用模型，也不把笔记自动注入创作提示词。

数据库是 `DATA_ROOT/data/meta/story_studies.sqlite3`；源码态位于项目本机 `data/meta/`，可用 `--data-root` 指定另一数据根。每次学习保留来源链接、作者、日期、批次、阅读范围、抽象经验和应用版本。规范化链接用于来源去重，完全相同的学习记录重复导入不增加历史，修订内容作为新记录保留。完整阅读后的片段复习不会把完成状态降级。

会员正文、账号资料、个人学习记录与样稿留在本机忽略目录，不提交 Git、不进入安装包。公共代码只采用审核过的通用方法，不复制原句、人物、独特设定或情节骨架。工具拒绝未定义的记录字段；这不能代替维护者对笔记内容的审阅。

在仓库根目录执行：

```powershell
$env:PYTHONIOENCODING='utf-8'
.venv/Scripts/python.exe tools/story_study.py catalog --input logs/catalog.json
.venv/Scripts/python.exe tools/story_study.py list --status unread
.venv/Scripts/python.exe tools/story_study.py record --input logs/reading-records.json
.venv/Scripts/python.exe tools/story_study.py list --status complete
.venv/Scripts/python.exe tools/story_study.py history --url "https://www.zhihu.com/market/paid_column/1823004053560553472/section/1832860582136647680"
```

`catalog` 输入是含 `title/url` 的 JSON 数组，可附 `author`。记录文件也是 JSON 数组，每条必填 `url/title/read_date/scope/coverage/lessons/batch_id`，可附 `author/applied_version`。`scope` 为 `opening/partial/full`；日期使用 `YYYY-MM-DD`；`lessons` 是 1～6 条简短的抽象经验。目录只收录已发现的链接，不表示已经读过。`list/history` 只读，缺少台账时返回空结果；损坏或不兼容的数据库报错并保留原文件。

## 第一批：盐选阅读（v5.3.0）

入口为用户提供的 [知乎盐选会员页](https://www.zhihu.com/fiore/h5/vip-web)。本轮从正常会员会话的官方页面响应确认正文授权成功、用户具有阅读权且正文未折叠，按页面字体显示核对可读内容，并检查故事结尾。下表的学习依据来自完整阅读，不只来自首页简介。

| 作品与来源 | 作者 | 阅读范围 | 可迁移经验 |
|---|---|---|---|
| [赵云舒](https://www.zhihu.com/market/paid_column/1823004053560553472/section/1832860582136647680) | 蜡笔小酒 | 正文及番外，至完结标记 | 用具体选择体现人物性格；关系变化由持续行动和承担代价表现 |
| [心迷宫](https://www.zhihu.com/market/paid_column/1632045792171855872/section/1830988835066097664) | 海绵小裤衩 | 开篇至第 25 节结尾 | 重复细节应提供新证据或改变理解；回到叙述框架时要带来新信息 |
| [神，但已读乱回](https://www.zhihu.com/market/paid_column/1949139575084675768/section/1948147476004598157) | 东隅 | 开篇至第 24 节结尾 | 喜剧也需要稳定规则；能力的条件、限制与代价参与高潮兑现 |

三篇本地阅读稿含段落分隔共约 4.24 万字符。逐篇结构分析与章节证据保存在本机 `data/meta/story_studies/round-2026-10-09.md`，本批记录使用 `salt-2026-10-09` 批次标识。本轮发现目录与已读来源合计 35 条，其中 3 条完整阅读、32 条未读；这是本次发现的批次，不是平台完整目录。下一轮先查台账，优先补充未读作品和尚未覆盖的类型，避免重复采样同一类故事。

三篇作品不能证明某种写法造成高赞。尤其不将强刺激题材、固定反转频率、字数切章、规定数量的象征物或某篇开放式结尾当作普遍要求。

## 采用的项目改进

[生成提示词](../story_prompt.py) 新增约 337 字符的可取舍指导，经典四种素材模式和纯净模式共用：

1. 让人物选择体现性格，代价贴合题意，可以是时间、劳动或让步；连续冲突应推动信息、筹码或关系，减少无变化的重复，不为煽情擅加悲剧。
2. 主线细节再次出现时承担新作用；不强制安插象征物，不套参考故事的事件顺序。
3. 特殊能力、制度或计谋的条件与限制先展示，再在高潮发挥作用；代价要有后果，核对条件前后一致，不能用术语替代因果或临时添加万能规则。

指导服从问题要求与参考文风，不增加格式门槛、规划请求或重写轮次。[配置](../config/story.py) 的 `CRAFT_LEARNING_ENABLE` 默认为 `True`；源码对照时设为 `False`，可撤回本轮指导并保留 v5.2.0 的叙事兑现自检。该设置进入 [演进方案记录](../core/evolution.py)，生成代码本身仍由既有指纹追踪，便于区分后续反馈属于哪个方案。

学习台账与正式创作分离：一条未经审阅的本地笔记不会改变正在运行的自动化。新的阅读经验需要经过小样验证、代码审阅和版本发布后，才成为默认创作指导。

## 验证与后续效果

本轮验证覆盖所有素材模式、纯净模式、独立关闭指导、重试反馈优先级、方案归属以及台账去重/事务/只读行为。实际网页模型另生成两题各一对样稿，使用同一题目和自创风格片段；旧组保留 v5.2.0 指导，新组只增加本批通用技法。每篇一次生成，样稿与耗时保留本机，独立编辑评审不读取实验映射。

首轮四次生成全部成功，独立编辑评审在日常题略偏好旧稿，在幻想题略偏好新稿。主审核发现日常新稿擅加了题目禁止的死亡背景，九天的重复场景对运营冲突解决帮助有限；幻想新稿虽更充分展示工具与代价，配重计算、制动和恢复运行仍有因果矛盾。旧稿也有座位计算或机械解释问题。因此补充题意优先、日常代价和因果核对的表达，保持指导可取舍。

篇幅按去空白字符与纯汉字分别核对，不能把换行计为正文超长：日常旧/新稿分别为 1543/1701 个去空白字符、1299/1385 个汉字；幻想旧/新稿分别为 729/897 个去空白字符、622/749 个汉字。两篇幻想稿按两种口径都低于要求的 1200～1600 字。首轮提示词增加 297 字符；定稿增加 337 字符。原始样稿、盲审及主审核修订保存在 `logs/salt-study/`，失败例子保留，不以新稿更长判定质量更好。

定稿后同题各复查一次，均成功返回：日常稿未出现死亡背景，并用移桌与劳动让步回应占地冲突；幻想稿展示规则和损坏的后果，但仍存在已冷却罐底继续供热、浆已吐完仍渗出等矛盾。两篇分别为 1421/1180 个去空白字符、1095/936 个汉字，用时 42.54/33.31 秒。该轮没有同期旧组，不能作为质量提升或加速证明；两篇按纯汉字口径仍不足篇幅，保留为后续改进对象。

样稿编辑评价不能预测读者互动。生成有随机性，少量耗时也不能证明同时间产出提高；同时核对篇幅、设定限制、重复细节的作用与结尾兑现，保留失败例子。

### 发布前观测基线

本轮以安装态 `%APPDATA%\AutoQuill` 的已有观测生成 `logs/growth-baseline-5.2.0-before-salt.json`，没有再刷新网页。发表日期自 2026-08-30 起，数据截止日为 2026-10-09；最近原始看板刷新为当日 00:01（亚洲/上海）。该基线包含历史版本与归属待确认的作品，不能全部归因于 v5.2.0。

账号数值与各指标有效样本量留在上述本地 JSON 和本批学习笔记，不提交公共仓库。复现时沿用 [增长报告口径](GROWTH-EXPERIMENTS.md)，输出到另一个文件保留本次基线。每个指标使用自己的有效样本，缺失与旧归一化零值不当作实测零；关注增长与每运行小时指标仍标为不可用。

发布后的真实反馈沿用 [增长实验方法](GROWTH-EXPERIMENTS.md)：按实际写作模式、题材和相同成熟窗口比较阅读与互动，核对作品归属和缺失数据。当前新增关注和每运行小时指标仍缺可靠观测，不根据点赞数推算。后续积累到可比较的作品样本后，再决定扩展、缩减或撤回本批指导。
