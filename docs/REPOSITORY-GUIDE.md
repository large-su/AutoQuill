# 仓库目录职责与清理规则

| 项目 | 内容 |
|---|---|
| **适用版本** | v5.0.8 起 |
| **最后更新** | 2026-10-01 |
| **状态** | 活跃 |
| **说明** | 源码、工具、历史资料、构建产物与用户数据的归属 |

## 目录职责

| 位置 | 内容 |
|---|---|
| 根目录 | 用户说明、变更日志、Agent 入口、CLI 与共享生成模块 |
| `core/`、`automation/`、`workflows/` | 共享能力、任务调度与流程编排 |
| `applications/`、`web_drivers/` | 业务浏览器适配与网页版模型驱动；部分模块动态加载 |
| `webui/` | API、本地控制台与静态资源 |
| `tools/` | 独立窗口、发布、专项验证及有明确用途的 CLI |
| `installer/` | PyInstaller spec、Inno Setup 源文件与语言资源 |
| `tests/`、`.github/workflows/` | 回归测试及跨平台 CI |
| `docs/` | 当前开发与操作规范；`docs/archive/` 保存历史复盘 |
| `tools/archive/probes/` | 有历史诊断价值的真机探针，仅在对应问题排查时查阅 |
| `config/`、`assets/` | 受控示例配置、只读资源；真实密钥与本机设置排除版本跟踪 |
| `build/`、`dist/`、`release/` | 生成的构建缓存、程序与安装包，不承载构建源文件 |
| `data/`、`logs/`、`output/` | 本机运行状态、业务资料和日志，排除版本跟踪 |

现有根目录共享模块仍被业务与冻结入口使用，按调用关系维护；目录整理不要求同时重写所有 import。

## 清理判定

1. 先用 `git ls-files` 确认源码范围，区分受控文件与本机运行产物。
2. 核对静态 import、动态注册、CLI、文档、测试与打包配置；独立 CLI 无 import 也可能仍有用途。
3. 已退役且无运行入口的实现从当前树删除，回溯交给 Git 历史。仍承担验证职责的探针保留，避免与普通发布混用。
4. 过时的操作手册移入 `docs/archive/`，更新当前入口；新规范保留单一权威来源。
5. 误入版本库的用户数据用 `git rm --cached` 取消跟踪并添加精确忽略项，本机文件保持完整。
6. 改动后核对引用与差异，运行相关回归；涉及跨目录构建源迁移时实际构建一次。

## v5.0.8 清理记录

- 删除 `archive/` 的 20 个退役文件：旧 OCR/UIA、知识库、图像链路及旧测试，均不参与当前生产导入或打包。
- 保留 99 个历史真机探针：部分仍是文档中的专项验证入口，未将“没有 import”当作废弃依据。
- 将受控 `AutoQuill.spec` 从构建缓存目录迁到 `installer/`，相对资源路径与冻结参数保持原有语义。
- 两份 `data/state/*.jsonl` 业务台账取消版本跟踪，本机内容已核对保持一致。
- 旧 Agent 操作实录和旧工作记忆转入历史目录，当前入口按任务指向权威文档。

退役源码可从清理前提交 `6e65a0a` 查询，例如 `git show 6e65a0a:archive/README.md`。恢复时先判断当前接口是否兼容。
