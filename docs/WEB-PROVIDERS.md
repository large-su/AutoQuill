## 选择与登录

设置 → 生成通道 → Web 网页版，选择本次使用的模型。新安装默认豆包，升级保留已保存的选择；未登录不妨碍保存选择，随后按提示登录目标网站。自动化沿用当前选择。

“网页版账号”提供每家独立的“登录”和“检查状态”。登录窗口固定打开所点的网站，检查其他网站不会切换当前模型。各网站的登录态保存在 AutoQuill 专用浏览器配置中，可以同时保留。任务或登录正在使用浏览器时，切换和新的浏览器操作会提示等待，以免抢占登录配置。

## 状态如何判断

| 状态 | 判据和下一步 |
|---|---|
| 已登录 | 目标站点的聊天界面和账号标志/有效格式凭据已出现，未见登录或限制提示。可以尝试生成；这不代表下一次请求一定被平台接受。 |
| 未登录 | 页面明确出现登录入口或跳转登录页。点击该网站的“登录”。 |
| 账号受限 | 平台弹窗或明确错误码表明账号封禁、禁言或停用。任务停止，自动化暂停；去官网查看期限或申诉，或手动改选其他模型。 |
| 需要验证 | 出现验证码或人工验证页面。打开对应网站完成验证后检查。 |
| 浏览器忙 | 当前任务、登录或检查正在占用浏览器。稍后重试，不能据此推断登录是否有效。 |
| 暂无法确认 | 网络、页面加载或网页结构无法提供足够证据。稍后重试；不据此判定退出或封号。 |

状态附带检查时间，未主动检查的网站显示“尚未检查”。DeepSeek 的账号限制还可由官网前端使用的 `40012`（封禁）和 `50006`（禁言）识别；`40002/40003` 属于认证失效。普通 HTTP 403、429、网络错误及 IP 限制不直接判为账号封禁。

网站可能只在发送时反馈限制，因此首页检查不能保证提前发现全部封禁。轮换平台是用户的手动选择，软件不自动重试受限账号，也不保证轮换可以避免平台风控。

## 适配与验证范围

豆包和 DeepSeek 沿用现有生成驱动。新增四家的输入、新对话、回复和完成状态依据公开页面及官方前端脚本校准；不调用未公开的生成接口，不接管用户日常 Edge 配置。

本版执行账号分类与路由回归，以及隔离 Edge 的回复提取、旧回复排除、思考过滤和未完成内容拦截验证。未获得其他网站的已登录账号，新增四家的真实账号端到端生成尚未验收。首次登录后先运行一次单篇任务，再用于自动化；网站后续改版时，无法确认完整新回复会停止交付。

新增四家通道暂保留网页历史对话，退出时关闭本次页面；不会用不确定的删除操作处理账号里的旧对话。现有豆包、DeepSeek 的自有会话清理行为保持原有实现。
