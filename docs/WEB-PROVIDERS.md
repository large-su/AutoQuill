## 选择与登录

设置 → 生成通道 → Web 网页版，先选择网站，再从该网站最近一次能力检查发现的目录中选择站内模型和思考强度。目录按网站保存；同名模型以完整路径 ID 区分。未检查或刷新失败时不会伪造默认模型，也不会接受未经发现的选项。目录中的图片和 DeepResearch 项标记 `selectable=false`，不进入标准文字 workflow。

“网页版账号”提供每家独立的“登录”和“检查状态”。登录窗口固定打开所点的网站，检查其他网站不会切换当前模型。各网站的登录态保存在 AutoQuill 专用浏览器配置中，可以同时保留。任务或登录正在使用浏览器时，切换和新的浏览器操作会提示等待，以免抢占登录配置。

## 状态如何判断

| 状态 | 判据和下一步 |
|---|---|
| 已登录 | 目标站点的聊天界面和账号标志/有效格式凭据已出现，未见登录或限制提示。可以尝试生成；这不代表下一次请求一定被平台接受。 |
| 未登录 | 页面明确出现登录入口或跳转登录页。点击该网站的“登录”。 |
| 账号受限 | 平台弹窗或明确错误码表明账号封禁、禁言或停用。任务停止，自动化暂停；去官网查看期限或申诉，或手动改选其他模型。 |
| 需要验证 | 出现验证码或人工验证页面。打开对应网站完成验证后检查。 |
| 浏览器忙 | 当前任务、登录或检查正在占用浏览器。稍后重试，不能据此推断登录是否有效。 |
| 暂无法确认 | 网络、页面加载或网页结构无法提供足够证据。稍后重试；不据此判定退出或封号。 |

状态附带检查时间，未主动检查的网站显示“尚未检查”。账号状态、能力目录和 workflow 验收是三类独立证据。能力检查记录模型新增、移除和参数更新；旧选择失效时必须重新选择。验证码、平台 busy 和账号受限都作为明确状态透传，不能伪装成生成失败或自动重试。DeepSeek 的账号限制还可由官网前端使用的 `40012`（封禁）和 `50006`（禁言）识别；`40002/40003` 属于认证失效。

网站可能只在发送时反馈限制，因此首页检查不能保证提前发现全部封禁。轮换平台是用户的手动选择，软件不自动重试受限账号，也不保证轮换可以避免平台风控。

## 统一交互契约

工作流只调用 `WebLLMDriver` 的站点无关生命周期：建立会话、站点设置、输入和发送、生成状态轮询、读取本轮完整回答、继续对话及清理本任务拥有的会话。`poll_generation()` 返回等待、思考、正文生成、完成或失败的统一快照；watchdog 只依据生成活动推进判定健康，串行等待和并行调度共用这套快照，站点差异留在驱动中。完成前不得读取旧答或未完成答。

`web_drivers/capabilities.py` 负责能力目录和每站点选择的持久化。能力发现不等于工作流验收；`record_validation()` 记录 workflow、模型、参数、版本、结果和证据。UI 只在当前模型与参数组合存在 `classic` 且结果为 `passed` 的记录时显示经典模式已验收。

## 适配与验证范围

豆包和 DeepSeek 沿用现有生成驱动。新增四家的输入、新对话、回复和完成状态依据公开页面及官方前端脚本校准；不调用未公开的生成接口，不接管用户日常 Edge 配置。

自动化测试覆盖能力目录、站点选择、统一生成快照、取消/登录/验证透传、会话归属和草稿保存边界。官方五家 classic/business 六项（筛选、评分、原创、回复、`profile_general`、`profile_author`）已有真实证据；clean/parallel 也按同一证据规则记录。DeepSeek 账号受限，明确忽略其真实测试并保留回归。真实经典模式须走选题、提取、生成、合规检查、知乎草稿服务端确认和本任务会话清理，并保存站点、模型、参数、版本和运行日志。

会话清理只针对本任务拥有且能精确识别的会话 ID，无法确认归属时保留清理责任，不删除用户已有聊天。千问输入超过 10000 字符时通过官网 TXT 附件传递完整提示，并检查输入与上传结果。

Aizex 每个新浏览器会话先登录中转站并点击“一键使用”，取得动态聊天站的授权。同一浏览器内复用这次授权建立独立聊天页面；动态地址只保留在当前浏览器内，不作为下次登录入口。模型目录按实际页面刷新，跨分组同名模型使用不同路径 ID。图像与 Deep Research 模型不用于标准文字工作流。

本版真实验收覆盖下列具体组合；“通过”指经典模式、筛选、评分、原创审核、回复生成、两种文风提炼、纯净与双页面并行生成均有通过证据，包含本任务聊天清理。目录中其他模型和参数仍需分别试跑。

| 网站 | 已验收的模型与参数 |
|---|---|
| 豆包 | 快速 |
| Kimi | 快速（k28-instant），标准强度 |
| 千问 | Qwen-快速，快速模式 |
| 元宝 | Hy3，快速回答 |
| 智谱清言 | GLM-5.3-Flash，快速强度 |
| Aizex | Gemini 系列 → Gemini 3.8 Flash [原生] |

Aizex GPT-6 高强度另有经典模式与六项业务交互的通过记录。Gemini 3.1 Pro 本轮出现上游响应中断，未计为通过；软件识别明确中断提示，保存诊断用部分内容并在原模型重试一次，连续中断则报错。Kimi 后续出现平台拥堵时同样保留失败状态，不把早先通过记录当作实时可用承诺。


真实验收：使用独立 `--data-dir` 与 profile；`tools/test_web_workflows.py` 支持 `classic`、`clean`、`interactions`、`business`、`generation`、`--checks`、`--visible`、`--human-verify`。classic 只写知乎草稿，不点公开发布，也不覆盖已有草稿。每条证据必须保存 provider、模型路径 ID、参数、workflow、版本、cleanup 和日志位置；最终矩阵以 `logs/web-workflows-runtime/logs` 与 `web-acceptance-lane-b/logs` 为准。
