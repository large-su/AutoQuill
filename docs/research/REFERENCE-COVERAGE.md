## 采用依据

默认 `sample` 路径以前由 `core/story_text.py::sample_reference_sections` 截取参考回答前 3000 字符。开头能展示人物处境与声口，却无法提供较后段落的对话推进、语气变化与收束表达。现有作者风格提炼器已有跨位置采样；本轮只补足默认逐篇生成路径的这一缺口，不修改作者提炼器或评分器。

2026-10-27 核对[知乎官方创作者手册](https://www.zhihu.com/knowledge-plan/manual)：平台建议内容结构清楚、语言精练、照顾读者，避免答非所问、标题党和洗稿；同时强调标题与开头的作用。因此新采样仍保留较大的开头份额。手册没有给出最佳采样比例，也没有证明本实现能提升账号关注；40/30/30 是工程试验参数。

盐选依据来自此前有会员权限时完整阅读的三篇旧资料，来源和阅读范围见[故事阅读学习](../STORY-LEARNING.md)。本轮复核其本地原稿和笔记中的表达方式：人物关系通过连续行动变化、重复细节承担新作用、结尾语气呼应前文。完整阅读笔记与片段采样分开，不能把几个片段当作已理解整篇因果。本轮电脑操作工具因无法可靠识别浏览器网址停止操作，未完成新作品在线阅读，未将旧资料重新登记为新读。

没有将会员正文、故事人物或具体情节写入代码。真实 API 对照只使用此前模型生成的本地虚构样稿作为参考，不发送会员资料。

## 实现与限制

`core/reference_sample.py::sample_reference_narrative` 对长参考取开头、中部与原文末段。扣除标签、两处省略说明和空行后，正文预算约按 40/30/30 分配，**最终返回字符串不超过 3000 字符**。窗口保持原文顺序且不重叠，边界优先向内收至近处段落或句末；不能保证每段对话都完整。短参考原样保留，不制造省略。

提示明确：片段之间不连续，原文末段不等于完整结局，不得猜测省略情节，不得续写参考或借用人物、事件和结构顺序。只学局部表达、场内推进和收束语气，新故事仍由题目决定。原有原创审核保留。

只对经典 `sample` 模式生效。纯净模式、全参考模式、配方及配方加参考模式不变，不增加常规生成、评分或重写调用，不更改自动化计划与发布配额。外层说明略有长度开销；相同参考预算不等于相同模型耗时，更不能直接换算成每小时阅读回报。

`config/story.py` 的 `REFERENCE_NARRATIVE_SAMPLE_ENABLE=False` 可恢复旧采样及原提示说明。每篇生成记录保存此开关，新模块进入代码指纹和发布演进历史；新增文件缺失的旧版本沿用原指纹算法，避免重算旧标识。历史未知配置不回填。

## 验证与效果观察

工程验收覆盖字符预算、真实末尾保留、窗口顺序与连续子串、边界输入、旧方案逐字对照、其他模式不变、零额外模型调用及方案归属。工程结果和 API 对照的实际统计记入 Release；样稿只用于发现问题，不代表增长验证。

三篇旧会员资料在本机的旧/新片段长度分别为 2989/2938、2936/2877、2964/2963 字符，新片段均保留原文末尾，包含标记仍低于预算。固定合成参考下，总 prompt 从 10335 到 10402 字符（增加 67 字符的净开销）；五条路径关闭开关时均与 v5.5.1 逐字相同，开启时其他四条路径不变，既有已发布版本的代码指纹保持一致。此处验证的是输入证据覆盖和兼容性，不是故事质量评分。

API 试验保留一次约 228 秒主动中止的长篇请求、有限输出预算下的空正文，以及显式模型对照记录。早期实验父进程加载了测试默认配置、请求子进程加载了安装态配置，其模型标签不作为实际请求模型的证据；该轮空正文不参加质量比较。最终对照显式请求 `deepseek-v4-pro` 并关闭思考，依据 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/) 使用请求参数；仅影响隔离实验，不保存到本机运行配置。各组使用相同参数、相同自有虚构参考，同题只改变采样开关，日常与奇幻题采用相反新旧顺序。它不等于当前网页登录通道的生产性能验证。

采用条件是参考证据覆盖确有扩大且工程边界通过；并不宣称比只看开头稳定写得更好。短片段无法证明跨章节伏笔已兑现，后续如出现模仿情节、断裂感或文风混杂，应缩减采样或关闭开关。

最终两题四份 API 试稿均返回正文，但都超出题目要求的 1200～1600 字。按纯汉字统计，日常旧/新为 4859/3909，奇幻旧/新为 3122/4804；对应耗时为 95.72/68.67 秒和 52.02/83.91 秒。两题方向相反且长度不同，不能据此宣称加速。既有格式检测均通过，却不能代表合题。

编辑复核认为日常新稿更直接围绕开放时间分歧并由双方承担成本；奇幻两稿仍有规则和因果问题，新稿的每日次数与早晚触发描述不协调，旧稿在十一点五十六分后立即触发预定中午的钟声，并引入缺少依据的挤位机制。主审核核对短引文及上下文后，修正了初评中过于宽松的规则判断。保留超长、规则矛盾与失败请求，不判定新方案稳定优于旧方案。样稿、引文核验与裁决留在本机 `logs/evolution-560-*.json`；未公开发布试稿。

2026-10-27 在本机冻结安装态既有反馈，查询截止日固定为当日，作品发布日期从 2026-09-01 起。最近真实观测为 2026-10-26 23:02:26（亚洲/上海），并非本轮新抓取。原件副本、来源 SHA256、7/14/30 天报告和摘要保存在本机 `logs/evolution-560-baseline/`，未纳入仓库与安装包。当前作品没有已确认的版本归属，仅可描述账号背景；新增关注与完整每运行小时回报继续标为不可用。

后续沿用[反馈观察口径](../FEEDBACK-OBSERVATIONS.md)，核对发布回执并确认归属，按同题材、同写作模式、同发布年龄比较开关开启和关闭的作品；同时列出有效样本、缺失、观测年龄、阅读/赞同/评论的中位数与 P25、每千阅读互动、最大单篇占比。窗口之间只有同一作品两端都存在真实观测时才计算增量。

先以每组至少 20 篇同窗口、可归属作品作为描述性复查门槛（这是本项目试验参数，不是显著性保证）；不足时报告证据不足。若连续两个可比较窗口未改善，或合题性、原创性、失败率或生成耗时恶化，优先关闭新开关并保留失败样本。关注数必须来自可核验的账号观测，不能用问题关注数替代；缺少完整运行暴露时间时不计算每小时回报。
