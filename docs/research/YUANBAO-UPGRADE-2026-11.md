## 本轮范围与验收

保持现有元宝生成、原创检查、格式检查与发布流程，改进生成和编辑评分中的题意兑现、连续叙述和关系推进。常规生成不增加规划或改写请求。使用相同题目、相同参考与同一元宝配置试稿；试稿仅存本地，不写知乎草稿或公开发布。

增长报告增加两次完整作品快照的集合比较：留存、缺失、新增作品分别统计；同一作品的指标变化只使用双侧有效观测。快照缺失不直接判定人工删除、平台下架或账号限制。

验收包含生成路径与评分契约回归、增长报告的集合和缺失语义、真实元宝试稿及人工编辑审读。模型评分与试稿不能替代后续 7/14/30 天真实读者反馈。安装包与 GitHub CI 结论见 [v5.12.0 Release 验证记录](https://github.com/large-su/AutoQuill/releases/tag/v5.12.0)；本机升级由用户进行。

## 已核实的现状

- 当前代码版本为 v5.11.0。v5.2～v5.6 已实施读者体验、盐选抽象技法、题意驱动结构与参考中尾段采样；v5.8 后补齐反馈归档，v5.10～v5.11 增加元宝等网页模型及站内参数选择。此前小样结果没有证明平台增长。
- 安装态数据与源码态数据分开。近期安装版任务日志确认实际生成站点为 Yuanbao，日志中的“网页当前模型”不能确认其子模型和思考强度。
- 近期稿件存在大量碎句、重复身体动作，以及关系/主线结果不充分的现象。现行公共守则仍要求“一句话超过 40 字必须拆”、单句数量额度与大量词语禁令；配方模板另有“禁止精确数字”。这些要求会与连贯表达及有效线索冲突。
- 作品快照集合在 11 月中旬发生大幅变化。具体账号数值、逐篇诊断和报告保存在本机 `logs/yuanbao-upgrade-20261125/`，不写入受控文档。

## 实施与验证结果

### 生成与编辑评分

修订 [story_prompt.py](../../story_prompt.py) 的公共行文指导，移除硬性句长、单句数字配额和大段逐词禁令，保留完整语意、有效动作、必要概述与自然声口。题目明确篇幅时，末尾自检和重试提示都服从该区间；默认篇幅继续保留。修正公共自检中直引号与「」互相冲突的要求。

[领域模板](../../applications/zhihu_story/prompts.py) 同步移除机械拆句提示和配方路径的精确数字禁令。现有评分六维、总分计算、片段预算和单次请求契约保持不变；编辑判断补充关系发展证据、无信息碎句和明确违反温暖甜文题意时的降档。

这些修改针对可复现的指令冲突，没有实现可靠的自动语义审稿，也不能保证模型遵守篇幅或消除事实错误。

### 元宝同题试稿

在独立数据目录与复制的浏览器 profile 中使用生产驱动，网页实读为 `Yuanbao / Hy3 / 快速回答`。两题使用相同自创参考、相同题目与独立会话，顺序在两题间交叉；生成结果只存本地。四次生成均完成，本任务会话清理获确认。

| 题目与方案 | 提示字符数 | 纯汉字 | 去空白字符 | 格式检查 |
|---|---:|---:|---:|---|
| 现代甜文，旧 | 7669 | 7567 | 9197 | 9/10 |
| 现代甜文，修订 | 6080 | 7086 | 8704 | 10/10 |
| 现实悬疑，旧 | 7648 | 4438 | 5323 | 9/10 |
| 现实悬疑，修订 | 6059 | 4337 | 5030 | 9/10 |

题目要求 4000～5000 字。甜文两稿均超长；悬疑按纯汉字口径在区间内，按去空白字符口径仍超上限。修订提示减少 1589 字符，但这不是生成加速的证据。

匿名编辑审读略偏好甜文旧稿的关系发展；悬疑修订稿的放票路径解释更充分，但存在日期与星期不一致。主审核实原文的日期、人物与路径描述后保留这些问题。旧悬疑稿同时声称通风窗铁网未拆与已经拆除，投票路线也有隔墙矛盾，不能因语言流畅就判定因果成立。

随后消除默认篇幅与题目上限的直接冲突，补测的快速回答甜文仍超长（8639 纯汉字、10379 去空白字符）。本轮不能宣布篇幅问题已经解决，也不判定修订方案稳定优于旧方案。最终采用依据为指令冲突修正；是否改善读者体验需要真实反馈。

### 深度思考模式的正文边界

补测 Hy3 深度思考时，发现返回文本包含“已深度思考”面板及写作计划，现有格式检查仍可通过。真实页面显示思考位于回答容器内部的 `.hyc-component-deepsearch-cot__think`，正文是该子树之外的内容。这个发现属于驱动提取缺陷，不能归因于故事文风。

[元宝驱动](../../web_drivers/yuanbao.py) 配置已验证的思考子树，由既有公共提取器排除，并单独记录思考进度；不按关键词截断故事。[隔离 DOM 回归](../../tests/test_web_provider_drivers.py) 在本机 Edge 的合成页面复现相同结构，验证混合回复只返回新正文、保留 Markdown，以及只有思考没有正文时不得完成。两项回归修复前失败，修复后通过，网页驱动专项共 20 项通过。

真实网页用同一 80～120 字微型故事请求复测，修复后只取得 114 个去空白正文字符，网页中的 1686 字符思考单独计数。响应完成、本任务会话清理和原快速回答模式恢复均获确认。该请求用于提取边界验收，不能套用生产长篇的章节与最低篇幅门槛。证据保存于 `yuanbao-dom-probe-after.json`、`yuanbao-deep-dom-after.html` 和 `final-check-browser.log`。

被思考文本污染的试稿不参与质量比较。修复不自动切换用户的回答模式。

### 作品快照集合比较

[增长报告](../../tools/growth_report.py) 新增成对的精确观测日期参数。集合比较只使用实际作品快照，不把 `evolution.json` 的历史观测当作当日完整集合。报告分别给出留存、后一快照缺失、新出现作品数量，以及每指标双侧有效的留存作品差值和分母；缺失不补成零，不输出作品 ID、题目或正文。合法空快照可以参与比较，错误 JSON 和错误 schema 不能冒充空集合。

```powershell
.venv/Scripts/python.exe tools/growth_report.py --data-root "$env:APPDATA\AutoQuill" --compare-from 2026-11-12 --compare-to 2026-11-25 --output logs/corpus-comparison.json
```

`--since` 继续约束原有成熟窗口；集合比较始终使用这两个日期的完整快照，报告以 `comparison_scope` 明示。新出现只表示此前快照没有，可以包含重新出现的旧作品。快照缺失不能区分主动删除、平台下架或采集范围变化。

## 阅读来源补充

复查既有私有阅读稿中的开篇、线索与收束段落，沿用已核实的三类方法：新信息改变人物选择、重复细节产生新作用、能力与规则在高潮承担真实限制。本轮不新增已完整阅读作品的数量，不把原文或具体情节自动注入生成。

[盐言故事主办论坛的创作者对谈](https://www.chinawriter.com.cn/n1/2025/0528/c404023-40489717.html)讨论人物的判断与选择推动情节，以及完整故事和表达密度；[《文艺报》对盐言近期创作的评论](https://wyb.chinawriter.com.cn/content/202603/16/content83120.html)讨论类型套路的审美疲劳及人物成长、情感和逻辑的结合。本轮把它们用作编辑方向，未将宣传数据或评论意见当作本账号的因果证据。

## 后续验证与采用范围

发布验收与本机安装分开记录。采用新版本后使用同一站点、明确的子模型及回答模式，沿用现有节奏积累新作品，并以生成指纹核对归属。

先查看发布后第 7～10 天的真实观测，再补第 14～17 天与 30～33 天；这些是比较窗口，不是平台流量规律。按题材和写作模式分组，报告阅读中位数/P25、每千阅读赞同与收藏、各自有效样本数和头部单篇占比。大批作品消失的日期单独报告集合变化，不混入同作品表现结论。没有明确子模型、方案归属或有效同龄观测时，保留未知。

这轮升级的已知作用是修正提示冲突、改进元宝正文提取与观测口径。账号增长是否回升，由后续作品表现验证。
