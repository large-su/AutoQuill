## 从作品转成能力

写作指导围绕“人物想争取什么，为什么值得在意；新信息怎样改变行动；对方怎样回应”。关系变化需要双方的相处和选择，对立者有自身目标与制约。温和故事可以通过照护、劳动、让步产生变化，不必强行制造恶人或悲剧。

经典生成原先主要依赖格式分，批量择优评分仍只看片段。本轮增加独立的全文终稿复核，按题意、因果、关系发展、主线收束和无变化的重复场景检查。批量评分用于候选排序，全文复核负责发现具体编辑问题，两者不等价。

`STORY_EDITOR_ENABLE=True` 默认启用。正常稿增加一次与当前通道一致的审核请求；复核给出最多三项问题，每项必须包含能在本稿核对的原文。因果矛盾必须有两处不同证据。核对原句只能证明证据存在，仍不能保证模型的语义判断正确；有意留白、超自然设定和不可靠叙述按题材解释。

发现实质问题时，在既有生成尝试次数内携带具体证据修正；不另外开启无上限改写。复核不可用、证据无法核对或正文超过 24,000 字符时保留本地候选稿并停止本篇发布，不能把片段审读当成全文通过。经典、纯净、质量优先批量路径共用此契约；启用编辑复核时批量采用质量优先生成。批量不会因为格式通过就再次放行 `ok=False` 的稿件。

明确写成阿拉伯数字区间的题目（如 `4000到5000字`）使用本地计数检查，口径为去空白正文字符、包含标点、不含 Markdown 数字章节标题。生成模板在插入参考前解除与总篇幅竞争的每节字数下限，单独给出全篇预算；原参考内容保持原样。未识别的中文数字或模糊篇幅不伪称已做精确检查。篇幅不合规可以被拦截，不能保证模型每次重写都会达标。

正文污染检查及发布前服务端全文读取继续执行。文学编辑复核针对生成稿；用户随后编辑过的草稿仍由发布边界的内容检查重新验收，不把早先的文学复核冒充后来正文的复核。

## 真实反馈与关注观测

现有每日反馈刷新成功后，复用登录浏览器向官方 `/api/v4/me?include=follower_count` 读取账号关注人数。独立最小记录为时间、账号标识、人数和固定来源，保存在 `data/state/account_metrics.jsonl`；不保存个人资料响应，不因作品删除而清空。读取失败保留未知，不阻断已取得的作品观测。

演进页展示单账号最新人数与首末真实观测净变化；首次观测不计算增长，多账号分别记录。账号统计独立于上方作品日期筛选，不将净关注分配给某一篇文章或某个模型。

增长报告增加赞同、评论、收藏、喜欢各自的每千阅读比率、有效样本数、P25、中位数、汇总比例和有效阅读分母。分组使用标题规则推定题材，并明确标注推定来源；版本、工作模式、运行方案和渠道/服务商/模型只使用已核验的发布证据链及生成时真实记录。闲置 API 设置不代表网页模型，未知不回填。

修正题材先验中的小样本保护：汇总已计算样本不足时的有效分，但消费方此前仍读取原始分。选题现在使用有效分，单篇异常高低互动不会突破既有最小样本规则。

## 后续判断

基线冻结于 2026-11-26；正式采用时间以用户更新后实际生成记录为准。源码提交时间、GitHub 发布日和安装日不能互相替代。先保持元宝站点、可观察子模型/回答模式与发布节奏稳定，不自动更改用户的模型选择或安装状态。

采用后第 7～10 天先查问题，再以第 14～17 天、30～33 天复查。按同题材、同写作模式、同发布年龄分组，主看每千阅读赞同的汇总与中位数，同时看收藏率、阅读中位数/P25、有效分母、最大单篇占比、生成尝试与可发布稿比例。账号关注净变化另列，不能据其总量认定某篇故事有效。

可先以每组约 20 篇可归因作品作为一次运营复查节点，这是检查预算，不是统计显著性门槛。记录缺失或样本过少时继续积累；删文造成的集合变化单列，不用删掉低表现作品后的均值抬升证明升级有效。若连续两个可比较窗口没有改善，或复核造成大量误拒、同质化和过高生成成本，优先调整/撤回对应指导和编辑策略，再用相同口径复查。
