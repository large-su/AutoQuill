# 每日作品反馈积累与演进查询

| 项目 | 内容 |
|---|---|
| **适用版本** | v5.4.0 起 |
| **最后更新** | 2026-10-14 |
| **状态** | 活跃 |
| **说明** | 每日采集如何保存真实观测、如何按作品发布年龄查询、如何保留版本归属和缺失证据 |

## 每天积累什么

日常自动化新增“反馈刷新”，默认每天本机时间 **23:00** 执行一次，可在自动化设置修改时间或关闭。
升级时保留既有任务配置和总开关；已有显式关闭不被覆盖。自动化总开关关闭或暂停时不自动采集。

任务复用“已发布内容看板”的完整刷新，不调用写作模型、不发送互动、不消耗写作或发布配额。
固定时刻不受写作的随机排班和运行窗口影响，执行仍与其他浏览器任务串行；浏览器忙时等候。
默认错过时刻可在当天补做；用户的“不补做”或“下个时段”策略保留。超过午夜的等候/重试明确标记未采集，次日重新排当日任务。
程序没有运行的日子不会生成虚构观测。只读反馈任务的中断可在当天恢复，其余有发布副作用的任务保持既有恢复策略。

一次成功采集保存：作品 ID、URL、发布时间、实际观测时间，以及阅读、赞同、评论、收藏、喜欢的累计值。
原始缺失指标为 `null`，明确显示的零为 `0`。同一作品、同一观测时点幂等写入；手动多次刷新可以留下多个真实时点。
观测时间取抓取完成时点，含本机时区；看板文件日期、演进观测和可选的旧表现台账使用同一个时点。

看板兼容的每日文件为 `data/published_answers_YYYY-MM-DD.json`，同日最新刷新替换它；
历次逐作品观测和刷新节点保存在 `data/state/evolution.json`，同日更早的真实观测不会因此消失。
这些文件都是本机运行数据，不进入 Git 或发布资产。

## 怎样看更新节点

已发布内容看板“数据快照”显示最近更新节点：实际时间、自动/手动、成功/失败/停止/中断，以及成功作品数。
演进记录显示最近成功时间和最新尝试，并提供“最近反馈采集记录”。自动化时间轴和执行台账保留每日任务状态。
仅查看这些页面不触发网络抓取；“从知乎更新反馈”才复用看板的手动刷新。

页面未取到有效数据、加载未到稳定终点、登录失效或演进观测保存失败时不能报成功。
质量异常不覆盖旧快照。成功观测已写入但程序尚未记录作业完成就退出时，同一个任务键会复用当天成功节点，避免恢复后重复抓取。
滚动采集最多 500 轮、时间预算 10 分钟；上限不是完整性的证明。只有加载数量连续稳定才确认完成，未到终点会保留旧数据并记录失败。

## 比较 7、14、30 天窗口

查询以**每篇作品的发布年龄**为准，不按采集所在的日历周把不同年龄的作品累计值混在一起。
沿用已有窗口：目标第 N 天到第 N+3 天内，优先最接近目标日、同年龄优先新的原始观测。
结果保留实际观测时间、实际年龄和发布日期精度；每日采集通常能提供更接近目标日的数据。
日期只有“日”精度时，这不是精确到小时的前 N×24 小时成绩。第 30 天累计值不能代替第 7 天值。

阅读、赞同、评论、收藏、喜欢分别选择有效观测，某项缺失不会让其他真实指标变成零或被丢弃。
页面和 JSON 查询分别显示：未到观察日、窗口缺失、发布时间未知、归属未确认。
节点分布使用已确认归属的作品，并报告每项有效样本、中位数、P25、均值和最大单篇占比。
统计总量保留作参考，不能单靠总量判断改进；作品数、成熟度、缺失和分布必须一起看。小样本和观察性反馈不能证明因果增长。

“相邻观测变化”只相减两个实际时点；`7→14`、`14→30` 的变化也要求两端都存在真实窗口观测。
缺一端则不可用，负差值保留（可能是撤回互动或平台修正）。差值覆盖的实际起止时点一并返回，不冒充精确自然日新增量。
阶段发文量由作品 ID 和发布日统计，而非相减账号总量；接口保留各节点的发布日期分布，后续可按所需期间重算。

## 作品属于哪个版本和行动

沿用生成文件 → 草稿 → 发布回执 → 公开快照的证据链，保留生成版本、generation ID 和实际方案 episode。
刷新的运行版本不会改写生成版本。不同配置的试用 episode 不混为一项行动；恢复旧配置仍是新的试用阶段。
旧台账只有明确作品 ID/回答 URL 与版本同记时才提供版本线索，标题或日期相近不构成归属证据。

现有人工确认/清除归属仍优先；缺完整证据的历史作品不自动塞进当前版本。
演进记录的“每次 Release”按明确生成版本筛选已确认作品，和“写作方案”按行动节点分组分开展示。
手改过稿件或发现发布回执关联不准确时，可在演进记录调整归属；查询不替用户自动确认。

## 后续评估的只读入口

页面支持指标选择、7/14/30/90 天观察阶段和作品发布日期范围。
本地 API：`GET /api/evolution/feedback?horizon=7&metric=likes&since=2026-10-14`；
可选 `until`、`aid`、`node_id`。`GET /api/evolution/refreshes` 查询刷新节点。

源码维护工具：

```powershell
$env:PYTHONIOENCODING='utf-8'
.venv/Scripts/python.exe tools/evolution_feedback.py --horizon 7 --metric likes --since 2026-10-14 --output logs/feedback-review-7d.json
.venv/Scripts/python.exe tools/evolution_feedback.py --horizon 14 --metric collects --aid <作品ID> --output logs/feedback-work-14d.json
```

安装版数据可加 `--data-root "$env:APPDATA\AutoQuill"`。
查询只读，输出另存新文件；拒绝覆盖输入 `data/config` 目录或已有报告。结果包含三种常用窗口的实际观测与差值，可供下一轮自我进化审核使用。
不要为了填满报告而补写过去的指标、归属、新增关注或运行时间；没有可靠采集的数据继续标为不可用。
