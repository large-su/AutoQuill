## 0. 归因口径与限制

- **版本归属**：按“生成事件时刻的 git HEAD（tag/commit 时间）”。8/21 前的发布（7/15-8/20）本地无运行日志/生成稿，只能按发布日期近似归属到当时版本，属间接推断。
- **发布口径**：AutoQuill 默认写知乎**草稿**，由你人工发布。发布率 = 日志可归因且出现在知乎已发布快照中的篇数 / 生成轮数；“未发布” = 仍留在草稿箱或已删除。
- **指标公平性**：阅读/赞同与曝光天数强相关（8/29 发布仅 1 天），因此除原始值外另按“发布后日均”归一；数据量小（每版本 1~12 篇），结论看趋势而非绝对值。

## 5. 结论：哪一版故事生成效果最好

- **内容效果综合最优：V4.7.0 之后、8/27 的两个 dev 版（量化克制守则 / 环境空镜治理）**。
  - 8/27 版产出全月最佳两篇：「有好看的先婚后爱这类型的小说推荐吗？」674 阅读 / 9 赞 / 3 收藏（3 天，日均 3 赞）；「你听过哪些匪夷所思的故事/经历？」521 阅读 / 8 赞。
  - 发布率 100% / 89%，仅 1 篇废稿；格式合规检测全过。
- 第二梯队：**V4.7.0（8/26 晚）**——单篇 100% 发布、零重试；“爽感硬约束+蒸馏法层”首战即发布。
- 第三梯队：**V4.6.1（8/25-26）**——单篇数据不错（「写小说怎么才会越写越流畅？」131/4/2评/5藏，互动质量最高；「被师姐毁容」305/3），但同题重复生成 5 次（去重 bug，v4.7.0 修复），可用轮次浪费约 40%。
- 垫底：V4.2.3（发布率 20%）、V4.4.0（2 轮 0 发布）、V4.3.0/4.5.0（发布率 50%；阅读中位 71 / 326）。
- **8/29（引言校验 dev 版）数据回落是三种因素叠加**：发布仅 1 天时间窗太短；守则收严致 2 篇废稿 + 重试率升高；DeepSeek 网页版前端改版导致 3 次 Web 通道失败（最后 1 轮直接挂掉）。不是“故事变差”的证据。
