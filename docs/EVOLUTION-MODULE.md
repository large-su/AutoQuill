## 默认版本归属

评价的最小间隔为北京时间自然日。同一天发布多个版本时，以当天最后发布的最新版本命名唯一评价节点；当天所有版本的改动、链接和提交记录都纳入节点详情。节点具有固定的 `day:YYYY-MM-DD` 标识，版本名可随当天后续发布更新。

节点从当天 `00:00:00+08:00` 起，到下一个有新版本发布的日期零点结束；没有新版本的日期继续归入前一节点。例如 A 版、B 版在 10 月 1 日先后发布，全天作品均归入 B 节点，A 的改动也属于 B 节点；下一次发布在 10 月 3 日时，10 月 2 日作品仍归 B。界面标为“按发布日推定”。不再把日内小版本分别评估。

这是用户约定的分析口径，不证明本机在软件发布后立即安装，也不证明该作品由此版生成。跨版本保存与发布时，“发布时推定版本”和“生成版本”可能不同，两者分别保留。更新版本时间会重新计算推定区间，不改写原指标、生成记录或人工方案归属。

GitHub 稳定版 `published_at` 优先；离线历史用 Git 提交时间并标明来源。本版安装包生成于 Release 上传之前，因此当前版本先使用“构建时间估计”，同步后采用实际发布时刻。旧日粒度时间标为估计，不能据此声称准确的运行暴露时间。

知乎时间按 UTC+08:00 解析，带时区值统一时区。完整年份优先，无年份按对应快照观测年份归一；仍保留日、分钟或秒精度用于追溯。按日评价只需要日期，日内时分不再切分样本。早于已知最早发布日、缺发布时间或没有公开快照的作品保持未归属。若同日版本只有日期而缺精确时刻，以版本号排序选取最新版本，并保留该排序来源。

旧演进状态曾截去时分。查询会从仍保留 `publish` 的原始每日快照恢复时间，不让旧日粒度状态覆盖它；查询不写业务原件。已经丢失的时间不能恢复。

## 三个更新入口

| 操作 | 实际行为 |
|---|---|
| 从知乎更新反馈 | 复用内容看板任务，保存逐作品真实指标与观测时间；采集进度、失败和最近成功时间可见 |
| 从本地快照更新 | 归档仍未保护的旧快照/旧台账观测，再从本机依据重算，不访问知乎或 GitHub |
| 同步版本时间 | 只读取本项目 GitHub Release 公共元数据；失败保留缓存，不影响知乎采集 |

每日自动化仍复用原有 23:00 反馈任务，不修改排班或发布配额。手动与自动刷新共享串行保护；登录失效、抓取不完整、停止或保存失败不能显示为成功。

## 每日原始快照与离线重建

自动化中的“每日内容快照”沿用 `feedback_refresh` 标识、原计划和每日一次的调度。完整采集经过现有质量检查后，先追加 `data/feedback_archive/<北京时间日期>/snapshot-<SHA256>.json`，再更新演进观测台账和看板镜像。每份独立档案含实际采集时刻、精度、来源、完整性、条数、原始指标和校验值。原子发布不覆盖已有档案，同日多次采集分别保留；内容与时刻相同的写入幂等。读取时校验结构与哈希，坏档跳过并显示问题。

`published_answers_YYYY-MM-DD.json` 继续作为兼容看板镜像，可以更新或清理。归档位于独立子目录，镜像操作不修改归档；已有归档后，镜像不再作为新的统计依据。快照内容保留原始指标的缺失和实测零，不能用补零伪造过去表现。

“从本地快照更新”保存仍可找到的旧每日文件，并将旧演进台账中尚无对应归档的观测按原时刻保留。旧每日文件只有日期时仍标日精度，旧台账保留已有观测时间，二者完整性为未知，不能算成新一次完整采集。已有旧文件归档后不再导入其被看板清理改写的版本。操作不重置原台账、生成证据、人工归属或用户配置。

归档是指标重建依据，派生状态缺失时仍可从有效快照和随包 Git 历史/本地版本时间缓存计算作品表现；生成证据、人工分配等非指标资料仍需原台账，不从快照猜造。查询与本地重建不启动浏览器、不联网；版本发布时间同步和知乎采集独立执行。`GET /api/evolution/archive` 返回覆盖状态，`POST /api/evolution/rebuild` 执行本地归档与重算。

首次本地重建或采集会建立跟踪起点。界面区分今日待采集、已记录和超过 23:00 仍缺失，并列出跟踪期内已结束日期的缺口。连续天数从最近成功日向前计算，旧导入记录不代表完整采集成功。失败尝试和最近成功仍分别可查；关机或登录失效导致的缺口不会用后来的累计指标回填。

同步每次读取最新 100 个 Release，合并保留已获取的旧记录。离线包保留固定代码历史基线；同步可补充基线前后版本时间，未随包提供的代码与配置详情未知。超出缓存覆盖范围的作品保持未归属。

## 生成证据与人工方案归属

方案视图继续保留生成记录。保存稿件时记录文件名、正文哈希、版本和白名单配置；连续相同指纹归入同一试用阶段，切换后再恢复则建立新阶段。不保存密钥、登录态或故事全文。

生成正文、保存草稿全文指纹、发布前服务端草稿指纹、回答 ID 回执及公开快照一致时，确认原生成版本。旧记录缺正文证据时仅为候选。正文变化、歧义、回执冲突及未公开记录不会自动确认。旧选题台账的运行版本不能冒充生成版本。

作品明细可人工选择方案并确认或清除，保留审计与历史观测。该操作独立于发布时间分组；清除方案不会删除作品或抹去其时间归属。人工选择其他方案不会凭空证明另一个生成版本。

相邻版本写作代码指纹相同时可归并为历史方案。指纹覆盖共享生成、评分、参考采样及提示词模块，不能证明模型、题材、配置或外部条件相同。

## 同龄反馈比较

作品年龄从知乎发布日期计算。7、14、30、90 天查询选择目标日至目标日 + 3 天内最接近目标日的一次有效观测；同日多次时优先最新有效值。只有第 60 天观测时，第 30 天仍缺失，不回填。

阅读、赞同、评论、收藏、喜欢分别统计有效样本、中位数、P25、篇均、合计及最大单篇占比。真实零保留，缺失为 `null`。旧归一化文件中的零可能来自解析失败，保留不确定性。未到观察日、无发布时间、成熟但错过窗口分别显示。小样本不判定胜负。

每日版本节点使用按发布日推定样本；节点的生成证据统计汇总该日包含的各生成版本，但仍与时间样本分开。采集日期不能改变归属，发布区间不能当实际运行小时分母。当前没有可核验的账号新增关注数据和完整运行时长，保持不可用，不用问题关注数替代。

## 文件与接口

| 文件 | 职责 |
|---|---|
| `core/evolution.py` | 本机方案、生成证据、观测及两套归属统计 |
| `core/release_windows.py` | 时间缓存、时区与区间匹配 |
| `core/feedback_archive.py` | 只追加原始归档、旧文件保护、校验与覆盖统计 |
| `core/evolution_history.json` | 随包版本与代码历史 |
| `tools/evolution_history.py` | 从 Git 生成历史，保留同提交的 GitHub 时间 |
| `webui/evolution_api.py` | 查询、方案确认、时间同步 |
| `webui/static/evolution.js` / `evolution.css` | 概览、版本导航、分布与明细 |
| `data/state/evolution.json` / `release_times.json` | 本机记录，排除版本跟踪 |

`GET /api/evolution/feedback?horizon=7&version=5.3.0&attribution_basis=publication` 查询该版本所在日节点的作品；即使指定当天较早版本，也映射到最终节点，`query.evaluation_version` 返回节点版本。省略 `attribution_basis` 时维持旧接口的 `evidence` 精确生成版本筛选；前端明确传入 `publication`。报告 `releases` 为每日节点，`release_history` 保留逐版本原件，节点含 `included_releases`、`release_count`、`interval_start/end`。`time_metrics` 和原证据 `metrics` 不交叉解释。

CLI：`python tools/evolution_feedback.py --horizon 7 --version 5.3.0 --attribution-basis publication --as-of 2026-10-27 --output logs/report-new.json`。`as_of` 仅限制观测，不重建当日版本缓存或人工分配状态。正式基线另存报告、输入哈希及时间来源，已有输出不可覆盖。

`POST /api/evolution/releases/refresh` 同步公共版本时间。`POST /api/evolution/assign` 接受 `{"aid":"回答ID","node_id":"方案ID"}`，`node_id:null` 清除方案；不改变知乎内容。

## 验证与可追踪基线

日内合并、动作保留、跨日边界、无更新日延续和成员版本查询由 `tests.test_evolution_days` 验证；原时区、精度恢复、联网失败与 API/CLI 由 `tests.test_release_windows`、`tests.test_evolution_query` 验证。生成证据与采集沿用 `tests.test_evolution*`、`tests.test_feedback_refresh_integration`。`AQ_UI_TESTS=1` 运行 `tests.test_evolution_ui`，隔离 Edge 检查实际交互与截图；合成数据不是实际反馈。

归档覆盖 `tests.test_feedback_archive`、`tests.test_evolution_archive` 和采集桥接专项，验证不可覆盖、幂等、校验损坏、日缺口、历史迁移、离线重建及镜像清理不删证据；`tests.test_archive_ui` 验证两个页面的本地重建入口和失败可见性。

本轮依据是用户 2026-10-27 的发布时间区间约定及随后明确的“至少一天、同日最终版本汇总”要求、GitHub `published_at` 与原始知乎 `publish` 字段。原指标不变，只调整归属统计。发布前冻结只读查询、时间来源和输入哈希到 `logs/version-window-*` 与 `logs/version-day-*`，账户数据不提交 Git。UI 和归属变化不表示阅读、互动或关注已提高；后续仍需比较相同作品年龄窗口及有效样本。
